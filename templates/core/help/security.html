Accounts & security

Signing in

Everyone signs in with a password and a 6-digit code from an authenticator app on their phone (Google Authenticator, Microsoft Authenticator, Authy…). You set this up the first time you sign in.

When you set it up you get 8 recovery codes. Keep them somewhere safe. Each one can be used once if you lose your phone.

After 5 wrong passwords in a row, an account is locked for 15 minutes. An administrator can unlock it sooner.

For administrators

Adding someone

  1. People → Add person. Choose their role.
  2. Copy the one-time sign-in link and send it to them privately. It expires after 3 days.
  3. Add them to the right projects from each project's Settings & members.

When someone leaves

Open their account and untick Active. They can't sign in any more, but their history stays. Do this on their last day.

Lost phone

On People, choose Reset 2FA for that person. They set it up again at their next sign-in.

Audit log

The audit log records sign-ins (including failures), permission changes, file uploads, BOM imports, stock changes and orders, with the time and IP address. Entries can't be edited or deleted from the app.

How your data is protected

  • All traffic is encrypted (HTTPS only, with HSTS).
  • Passwords are stored as salted PBKDF2 hashes; two-factor secrets are encrypted in the database.
  • Uploaded files are only served to people who can see the project — there are no public file links.
  • The site loads no third-party scripts, fonts or trackers, and sends a strict Content Security Policy.
  • Forms are protected against cross-site request forgery; the GitHub webhook is protected by a signature instead.
