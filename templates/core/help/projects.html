Projects & tasks

Projects

A project is a product or board you're developing, like “Power board” or “Sensor node”. Each project has a short key (e.g. PWR) that prefixes its task IDs: PWR-1, PWR-2…

Leads and administrators create projects and choose members. Engineers only see projects they're a member of.

Revisions

A revision is one spin of the board: Rev A, Rev B, or EVT/DVT/PVT. Each revision has its own BOM, and you can tie tasks to a revision to see what's left before it's ready. Revision statuses:

  • In design — schematic and layout are being worked on.
  • In review — design is complete and being checked.
  • Released for production — frozen. Only leads can change its BOM.
  • Obsolete — replaced by a newer revision.

Release checklist

Each revision has a release checklist (its page is linked from the project overview). A new revision starts with a standard design-review list: ERC and DRC clean, MPNs complete, footprints checked, ESD and decoupling reviewed, BOM compared, and so on. Add or remove items to suit the board. Each item is signed off with your name and the time. A revision can only be marked Released for production once every item is signed off.

Tasks

Every task has a type (firmware, schematic, PCB layout, mechanical, test, production), an assignee, an optional reviewer, a priority and a due date.

ColumnMeans
To doAgreed and ready to start.
In progressSomeone is working on it.
In reviewWork is done and waiting for the reviewer. Opening a pull request moves the task here automatically.
DoneReviewed and merged or accepted. Merging the pull request moves it here automatically.

Move tasks by dragging cards on the Board, or with the status buttons on the task page.

Writing good tasks

  • Start the title with a verb: “Route USB-C connector and add ESD protection”.
  • In the description, say how you'll know it's done: “DRC clean, ESD diodes within 5 mm of connector”.
  • Attach reference material: datasheet pages, scope captures, previous test results.

Formatting in descriptions, comments and chat

**bold**, `code`, ```code block```, links are clickable, task IDs like PWR-12 become links, and @username notifies that person.
