Connecting GitHub

Workbench receives events from GitHub through a webhook. It never needs your GitHub password or a token, and it can't change your repositories.

One-time setup (administrator)

  1. Generate a long random secret on the server, e.g. python3 -c "import secrets; print(secrets.token_hex(32))", and set it as WORKBENCH_GITHUB_WEBHOOK_SECRET. Restart Workbench.
  2. In Workbench, open each project's Settings & members and fill in its GitHub repository (owner/name).
  3. In GitHub, open the repository → Settings → Webhooks → Add webhook:
    • Payload URL: shown on the GitHub page
    • Content type: application/json
    • Secret: the same secret from step 1
    • Events: choose Let me select individual events and tick Pull requests, Pull request reviews, Pushes and Workflow runs.
  4. GitHub sends a test “ping”. It shows as processed in Recent webhook deliveries on the GitHub page.

For a GitHub organisation you can add the webhook once at organisation level instead of per repository.

How work gets linked

Workbench looks for task IDs (like PWR-12) in pull request titles, branch names and descriptions, and in commit messages. Only IDs whose key matches the project linked to that repository are used.

Security

  • Every delivery is checked against the secret with an HMAC-SHA256 signature. Deliveries with a missing or wrong signature are rejected and logged.
  • Each delivery ID is accepted only once, so captured requests can't be replayed.
  • If you think the secret leaked, generate a new one and update it on the server and in GitHub.

Recommended: KiBot in GitHub Actions

Add docs/examples/kibot.yml from the Workbench repository to your hardware repos as .github/workflows/kibot.yml. On every pull request it runs ERC and DRC and produces schematic PDFs, Gerbers and a BOM CSV. Workbench shows the pass/fail result on the task and posts failures to chat.
