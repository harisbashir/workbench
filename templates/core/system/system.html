Good to know

  • Updating: git pull then docker compose up -d --build. Your data folder is kept.
  • Backups are zip files in data/backups. Copy them somewhere else too — a backup on the same disk won't survive a disk failure.
  • Moving to a new server: copy the whole data folder across and start Workbench there.
  • Health check for monitoring: /healthz

Stored on the server in data/backups (next to docker-compose.yml). Each backup holds the database, every file and the encryption keys — keep downloads somewhere safe.

Restoring a backup

Restoring replaces everything with the backup's contents. Your current data is kept in a pre-restore-… folder just in case. On the server:

docker compose stop workbench
docker compose run --rm workbench restore workbench-YYYYMMDD-HHMMSS.zip
docker compose start workbench

To restore on a new server, put the zip in data/backups/ first.

Why set up email?

Email is optional. When it's on, people get their notifications (assignments, review requests, @mentions, failed checks) by email as well, grouped into one message per minute. Each person can turn this off in their profile.

Gmail / Google Workspace: smtp.gmail.com, port 587, STARTTLS, and an app password.

Microsoft 365: smtp.office365.com, port 587, STARTTLS.

The password is stored encrypted.
