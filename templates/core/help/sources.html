Sources: code and design files

Sources keeps the files you're working on — firmware code, KiCad projects, scripts — with every version saved. You can see what changed between any two versions, go back to an old one, and stop two people changing the same KiCad file at once. It needs no GitHub account and works the same whether files are stored on the server or in Amazon S3.

Sources is for work in progress. Final Gerbers stay on each board revision under Hardware, and released firmware stays under Firmware.

Repositories

A repository is a set of files kept together, for example Main MCU firmware or Power board KiCad. Add them under the project's Sources tab, or from a board's page. Give each one:

  • a board, or none for files the whole project shares,
  • a kind: firmware code, KiCad design or other,
  • for firmware, the controller it runs on and the firmware its versions are released as.

Checking in a new version

  1. Open the repository and choose Check in new version.
  2. Choose changed files, a whole folder, or a zip (a zip is unpacked, keeping its folders). Choose whether files you don't upload are kept or deleted — use "deleted" when your upload is the whole project.
  3. Workbench shows what will change: new, changed, deleted and unchanged files. Backups, caches and .git folders are left out automatically.
  4. Write a short message saying what changed — mention task IDs like PWR-12 — and press Check in. It becomes the next version: v1, v2, v3…

When two people work on the same files

  • Changed by someone else: Workbench remembers which version you started from. If someone else changed the same file since then, that file is refused instead of overwriting their work. Download the latest version, merge your changes, and check in again. Files nobody else touched can still go in.
  • Checking out KiCad files: schematics (.kicad_sch) and PCBs (.kicad_pcb) don't merge well, so you check out a file before changing it. While it's checked out to you, nobody else can check in a change to it. Checking in your change releases it. You can check out any other file too.
  • A lead or administrator can release someone else's check-out, for example when they're away. The person is told.

Looking at files and changes

  • Code is shown with colours for the language, line numbers, and a link to each line (click the number).
  • Changes next to each version shows what changed in it, line by line. Compare any two versions, one column or side by side.
  • Download any version as a zip, or a single file.

KiCad previews

KiCad 6, 7, 8 and 9 files open as drawings instead of text:

  • Schematics (.kicad_sch) show the sheet with its parts, wires, labels and sub-sheets. Click a part to see its reference, value and footprint; click a sub-sheet box to open it. A sheet used more than once (two copies of the same channel, say) shows the references of the copy you opened it from. The list beside the sheet shows every part and named net.
  • PCBs (.kicad_pcb) open in the same viewer as Gerbers: top, bottom and every layer, with solder mask colours and measuring.
  • Compare with the previous version lists the parts added, removed and changed (value, footprint, moved, rotated), and the nets that changed, then shows both versions side by side with the changes coloured: green added, red removed, amber changed.

The previews are drawn by Workbench itself, so they look close to KiCad but not identical — fonts and some details (like special pad shapes) are simplified. View as text always shows the exact file. Files saved by KiCad 5 or older need to be opened and saved in a newer KiCad first.

From Sources to production

  • Firmware: on a firmware repository, Make a firmware release creates a draft release of the linked firmware with that version's source attached. Upload the built .bin/.hex to the release and take it through testing as usual.
  • KiCad: on a KiCad repository, Mark as built from records which design version a board revision's Gerbers came from. The revision page then shows "Built from Power board KiCad v22". A repository that a released revision was built from can't be deleted.

Limits

A check-in can have up to 5,000 files, and up to 1,000 when you choose a folder (use a zip for more). Choosing a folder needs JavaScript in your browser; without it, zip the folder and upload the zip. A zip can hold up to 20,000 entries. The size limits are the same as for file uploads. Windows program files (.exe, .msi, .dll…) are refused; zip them and tick “Keep zip files as zips” if you need to keep one. Scripts and web files are fine, and are only ever downloaded, never run.
